# Claudex 2.0.4

Released on 2026-10-19. App **2.0.4** bundles Claude Mod **0.8.62**.
[Release and downloads](https://github.com/jamie950315/claudex/releases/tag/v2.0.4).
App and Mod versions are separate. These notes summarize changes since 2.0.3
(Mod 0.8.61).

## Claude sidebar compatibility

- Fix the folders adapter refusal on the Claude frontend deployment that creates
  Code project/environment grouping components through a factory rather than
  referencing the project component directly in its routing table.
- Follow the factory's structure and native JSX route to the existing proved
  folder consumer. Accept only an immutable synchronous wrapper with inert
  constant arguments and a single returned component. Async, reassigned,
  effectful or disconnected wrappers remain refused.
- Preserve the existing direct-component path and all native identity, ownership,
  installation, archival and recovery proofs. Other structural changes can still
  require an adapter update; unsupported routes remain visible failures.

## One Rust engine

- Archive the former JavaScript engine and reference suite on
  [codex/javascript-legacy](https://github.com/jamie950315/claudex/tree/codex/javascript-legacy).
  Current builds and tests use the Rust workspace without that engine.
- Retain the JavaScript required by Claude Mod, the signed Codex native host and
  Claude renderer injection. The six renderer host programs moved unchanged
  into their owning Rust crate; frontend maintenance tools use the Rust checker,
  with independent static syntax and AST checks.
- Replace legacy-engine test execution with frozen contract fixtures and
  Rust-backed host checks. End-user installation still uses the native app and
  does not require Node.js, Git or a compiler.

## Verification

- All 37 affected Rust frontend tests, 14 published-graph/watch host tests,
  40 Mod controller tests and 26 native Mod kit tests passed. CLI version/help
  and official strict Mod validation passed.
- The new published frontend graph passed all four adapters across 3,078 modules.
  Both old and new copied native-cache graphs passed selection, syntax and
  native AST/wiring checks. The old graph retained identical adapter-selection
  and wiring metadata.
- Copied-cache installation, idempotent reinstall, exact restore and an actual
  filesystem-watch transition passed without changing live source caches.
- The signed app was installed through normal app-owned setup. After a
  user-authorized normal Claude restart, native logs confirmed all four adapter
  resources loaded; synchronization was ready and the restart request cleared.
  The actual Code sidebar rendered its project folders successfully.
- The release ZIP was extracted and passed complete deep/strict signature
  verification. Its native engine and host payload match the accepted candidate
  and current source, with App 2.0.4 and bundled Mod 0.8.62.
- No model prompt or inference was used for this repair's acceptance. Existing
  sessions can retain an older loaded Mod until their normal lifecycle loads
  the installed update; installed payload and loaded-session versions are
  reported separately.

## Distribution

Apple Silicon, macOS 13 or later. The app has an Apple Development signature
and is not notarized. `Claudex-v2.0.4-macOS-arm64.zip` and `SHA256SUMS` are
available on the release page.
