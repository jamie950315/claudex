# Claudex 2.0.1

Released on 2026-10-17. App **2.0.1** bundles Claude Mod **0.8.50**.
[Release and downloads](https://github.com/jamie950315/claudex/releases/tag/v2.0.1).
App and Mod versions are separate. These notes summarize changes since 2.0.0
(Mod 0.8.49).

## Synchronization watcher and active-tail resilience

- **Active-tail provenance and in-progress waits:** when a tracked conversation
  is actively appending a new turn or flushing its rollout while the watcher
  inspects it, transient active-tail waits (`IncompleteTurn`,
  `ConcurrentTranscriptWrite`, and `NativeProvenanceChanged`) now schedule a
  bounded follow-up pass without inserting the conversation into
  `blockedConversations` or displaying a false "Some conversations are paused"
  warning in the menu bar. Genuine structural, ownership, or integrity failures
  still pause affected conversations and surface immediately.
- **Single-verification image provenance promotion:** Codex image provenance
  already verifies the rollout file identity before and after reading lines in
  `Provenance::hydrate`. Removing a redundant second `self.verify()` after slow
  PNG/JPEG decoding and conversion in `ImageEvidence::promote` prevents active
  long conversations with embedded images from failing with
  `Native provenance source changed during verification.` when a new turn appends
  to the rollout during image processing.
- **Uncompressed rollout length inspection:** `Runtime::inspect` reads the length
  of uncompressed `.jsonl` Codex rollouts directly from the verified file
  identity instead of re-reading and parsing the rollout a second time after
  `read_snapshot`, eliminating an unnecessary race window on active rollouts.
- **Concurrent sync-events inbox access:** `Inbox::read`, `Inbox::write`, and
  `Inbox::lock` retry boundedly across concurrent atomic `inbox.json`
  replacements and `inbox.lock` contention or release between hook writers and
  the background watcher (`lock_contention` and `retryable_current_lock`),
  preventing the watcher loop from exiting when a hook updates `inbox.json`
  mid-read.

## Verification

- **Automated suite:** 349 Rust workspace unit and integration tests passed
  (`cargo test --locked --workspace`, with 6 opt-in live-runtime tests ignored)
  plus 7 Node entry-point compatibility tests (`npm run test:entrypoints`),
  zero failures. The staged Mod `0.8.50` companion passed official strict
  validation (`claude plugin validate --strict`) and all 26 native Mod kit
  tests.
- **Live watcher and active-conversation verification:** verified on the
  installed macOS service that an active 47 MB / 5,026-message Codex
  conversation with 17 embedded images (`b39749ec-b41a-4926-b9a5-0e03cbd10a43`)
  completed full synchronization to Claude (`messages: 5026`,
  `synchronization: "ready"`, `initialSweepRemaining: 0`,
  `blockedConversationCount: 0`) without false pause warnings or watcher
  process exits.
