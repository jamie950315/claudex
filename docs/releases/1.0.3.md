# Claudex 1.0.3

This update follows conversations when a project is renamed or moved, keeps more
real-world histories synchronizing, and lets collaboration sub-agents work like the
user's own agent when that is explicitly chosen.

## Changes since 1.0.2

### Synchronization

- Follow Codex conversations whose project directory was renamed or moved. The old
  directory must be gone or an alias of the new one and the synchronized history
  unchanged; the Claude counterpart is then replaced by one in the new project.
  The previous Claude conversation and its Desktop entry are kept.
- A renamed project no longer stops the whole service or the Claude folder map:
  only the affected conversations wait until the move is verified.
- Accept Claude Code 2.1.284 `/compact` histories that keep recent messages by
  reference, when those messages already exist in the retained history.
- Codex conversations forked from, or rolled over from, earlier ones now recover
  images inherited from those earlier rollouts, through the exact references Codex
  records and nothing else.
- Interrupted Codex turns that contain images are no longer treated as incomplete.
- Newly enrolled conversations omit the display-only screenshots Codex Desktop
  stores for Browser Use and computer-use calls. They are not model input and could
  make a history exceed the export limit. Existing conversations keep their exact
  representation.
- A Codex conversation larger than the export limit is reported as an unsupported
  source instead of restarting the service repeatedly.
- Each blocked conversation is listed once in status, and an original left behind
  by a project move no longer stops Local entry archival for every conversation.

### Collaboration

- Optional full-access sub-agents: when chosen in the app or by the controller,
  workers run with the user's normal settings, plugins, MCP servers, hooks and
  login-shell PATH. Read-only and workspace-write remain the sandboxed defaults.
- Work whose result is uncertain is closed automatically as failed once its
  processes have provably exited, and now blocks only related work rather than all
  dispatch. Writable work is flagged for review; nothing is replayed.
- Native token usage is recorded for every invocation and totaled per provider.
- The app adds a default-permission picker and a Resolve action for uncertain work.

## Distribution and limits

The graphical build targets Apple Silicon Macs running macOS 13 or later and
requires existing Codex/ChatGPT and Claude Desktop installations with native
account access. Required sign-ins, permissions and hook trust remain in effect.

This build is **Apple Development signed, not Developer ID signed or notarized**.
Clean-user/clean-machine installation acceptance has not been completed. Do not
disable macOS security controls to hide this limitation.

Full-access sub-agents can change anything the user can; choose it only when that
is intended. Native app updates can still require adaptation; unknown formats pause
the affected conversation explicitly rather than guessing. See the
[app guide](https://github.com/jamie950315/claudex/blob/v1.0.3/docs/app.md),
[synchronization guide](https://github.com/jamie950315/claudex/blob/v1.0.3/docs/synchronization.md)
and [collaboration guide](https://github.com/jamie950315/claudex/blob/v1.0.3/docs/collaboration.md)
for the exact boundaries.
