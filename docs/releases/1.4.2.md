# Claudex 1.4.2

Released on 2026-10-12. App **1.4.2** bundles Claude Mod **0.8.24**.
[Release and downloads](https://github.com/jamie950315/claudex/releases/tag/v1.4.2).
App and Mod versions are separate. These notes summarize changes since the
development build 1.4.1, which introduced compaction at the end of a Claude
Code warm-up and has [its own notes](1.4.1.md); the last published release
was 1.4.0.

## A finished Codex warm-up compacts its conversation too

- A Codex warm-up that reached its limit is now compacted once as well,
  25 minutes after its last warm request started, inside the 30-minute cache
  window Claudex assumes for Codex. **When warming ends** in the Cache
  settings window now applies to both apps and stays on by default.
- Claudex asks the Desktop window that owns the conversation to compact it,
  with the request Desktop's own windows use. It reports the compaction only
  after the native turn announced it and completed; anything else is shown as
  uncertain and never tried again.
- `/claudex:warm on compact=off` (or `compact=on`) in the Codex page decides
  for that chat only. `/claudex:warm status` shows whether and when the chat
  will be compacted.
- As in Claude, nothing is compacted once the window has passed, while the
  chat is busy, after its model, effort or settings changed, or after a
  message of your own that followed the end of the limit. A draft in the
  Codex composer cannot be seen and does not prevent it.
- The limit's end time no longer disconnects a Codex warm-up whose compaction
  is still due.

## Claude compaction now works in Claude Desktop

- 1.4.1 asked Claude Code to compact with a call that real Claude Desktop
  sessions refuse, so nothing was compacted there and the attempt ended as
  uncertain. The Mod now runs the native `/compact` command and takes the
  compaction's own native result as its evidence.

## A reply without tool calls no longer stops Claude warming

- On Claude Code 2.1.293 and 2.1.295 a warm request does not re-read the last
  user message of the request before it. After a plain reply, with no tool
  call, every warm request therefore came up a few dozen to a few hundred
  tokens short of the whole prefix and warming stopped with
  `native-cache-verification-failed`.
- A warm request now also counts as a cache hit when it re-read more than the
  request before it had re-read, and its own read and write cover that prefix
  again. Reading only what was cached before that request is still a miss.
  Codex is unchanged.

Claude compaction was accepted in one authorized real run on Claude Code
2.1.295: a verified warm request, then one native compaction requested 240
seconds after that request started, inside its five-minute window (34,422 to
1,728 tokens), and a normal reply afterwards. The Codex side was checked with
injected data only: the Desktop request was read from the shipped Codex
Desktop bundle and no real Codex compaction was run for this release.

## Distribution

Apple Silicon, macOS 13 or later. The app has a development signature and is
not notarized.
