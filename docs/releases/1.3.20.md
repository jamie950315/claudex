# Claudex 1.3.20

Development build of 2026-10-10; not yet a published release. App **1.3.20**
bundles Claude Mod **0.8.22**. These notes summarize changes since 1.3.19.

## Your own message starts the warming limit over

- In the Cache settings window, **When you send a message** now offers **Keep
  warming and start the limit over** (the default) and **Stop warming**.
- Starting over counts the chosen limit again from the reply to your message:
  `for=4h` runs four more hours and `rounds=3` allows three more requests.
  Before, only the next warm request was timed again and the limit kept
  running out.
- An `until=` limit keeps its clock time; only its request count starts again.
  This needs a conversation that loaded Mod 0.8.22; an older loaded Mod sends
  the limit as a duration.
- A limit that has already used up its time or its requests has ended and is
  not started again. A reply that ends in an error, and the tool steps before
  a reply, change nothing.

## A prompt sent from the iOS remote and blocked locally no longer pauses its conversation

- Codex records where a turn was submitted from. An empty turn was accepted
  only from the Desktop composer, so a locally blocked prompt sent from the
  iOS remote paused that conversation with "empty turn start differs from the
  API". The observed `remote_ios` form is accepted now; every other trigger
  and every agent-initiated start are still refused.

Checked with injected data, the affected real rollout (read only), the native
validator and the native test kit.
