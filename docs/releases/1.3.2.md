# Claudex 1.3.2

Development build of 2026-10-10; not yet a published release. App **1.3.2**
bundles Claude Mod **0.8.15**. The bundled Mod payload is unchanged. These notes
summarize changes since 1.3.1.

## A frontend update no longer needs a second manual Claude restart

- When Claude Desktop starts and fetches a new frontend, it evaluates those
  files before Claudex can patch them. Folder placement, chat wake, owner wake
  and the `/claudex` entry then stayed unloaded until Claude was restarted
  again by hand.
- Claudex now makes that restart itself, once, while Claude Desktop has only
  just been opened: the process is at most two minutes old, no Code session
  process runs beneath it, no prompt has been submitted since it started,
  every enabled adapter is installed for the new frontend and at least one was
  written during this start.
- It asks the application to quit and reopens it. It never signals the
  process, never repeats for the same frontend, restarts at most twice in ten
  minutes and treats a declined quit as final.
- In every other situation nothing is restarted and the resource stays
  `restart-required`, as before. `rendererAdapters.relaunchAfterUpdate: false`
  disables the automatic restart.

A draft typed into the composer during those first moments is not visible from
outside the renderer and would be lost by the restart.

Checked with injected process, clock and inbox data. No real Claude Desktop was
restarted by a test, and the behaviour has not yet been observed on a real
frontend update.
