# Claudex 1.0.2

This update makes synchronization and collaboration more resilient on long-running
machines: it recovers from more native app behaviors on its own, keeps unrelated
conversations moving when one is held, and closes several file-safety gaps.

## Changes since 1.0.1

### Synchronization

- Synchronize Claude Desktop forks as their own conversations once their copied
  rows are proven to match the parent; unproven forks stay reported as unsupported
  sources instead of crashing the watcher.
- Freeze a conversation whose working directory was deleted (for example a
  cleaned-up Codex worktree). Only that conversation pauses; others keep syncing.
- Stop and resume tracking of a conversation explicitly, and preserve an
  independently continued Claude original as its own conversation instead of
  choosing between the branches.
- Reopen Codex Desktop once, gracefully, when login window restoration started it
  without the Claudex launcher. A running Codex turn defers this; a declined quit
  is never forced.
- Accept newer observed native history shapes: streamed tool blocks after partial
  results, mixed local and inline images, and initial native goal requests, each
  with exact provenance checks.
- Keep unsupported-source diagnostics visible across unrelated events and tolerate
  device renumbering after a reboot without restart loops.
- Faster complete-history verification and less idle work.

### Collaboration

- Track native descendants in other process groups through exact identities, and
  retire descendants that have provably exited. Long, test-heavy tasks no longer
  stop as uncertain after 256 short-lived processes; the bound now covers
  descendants that are still running.
- Let the controller close work whose process inventory was interrupted, after
  inspecting the machine, with an explicit attestation. Previously such work could
  block Quit permanently. The leader, its process group and recorded descendants
  must still be absent, and the original evidence is kept.
- Concurrent native hooks no longer fail coordination under lock contention.

### App and file safety

- Accept a locally re-signed official Claude build (official bundle identifier,
  ad-hoc signature, strict deep verification) and label it as a local build.
- Read-only app inspection refuses every mutation, and service control verifies the
  exact loaded launchd job before acting on it.
- Staging writes refuse hard-linked or non-regular staging files, Claude appends
  verify the exact snapshotted file identity, and cached proofs never block on a
  FIFO.
- The app builder rejects portable Node runtimes that lack required APIs.
- The pinned Claude Desktop wake resource was updated for the current Claude
  frontend; earlier resource originals and journals are preserved.

## Distribution and limits

The graphical build targets Apple Silicon Macs running macOS 13 or later and
requires existing Codex/ChatGPT and Claude Desktop installations with native
account access. Required sign-ins, permissions and hook trust remain in effect.

This build is **Apple Development signed, not Developer ID signed or notarized**.
Clean-user/clean-machine installation acceptance has not been completed. Do not
disable macOS security controls to hide this limitation.

Native app updates can still require adaptation; unknown formats pause the affected
conversation explicitly rather than guessing. Uncertain collaboration work still
blocks new dispatch until it is explicitly reconciled and is never silently
replayed. See the [app guide](https://github.com/jamie950315/claudex/blob/v1.0.2/docs/app.md),
[synchronization guide](https://github.com/jamie950315/claudex/blob/v1.0.2/docs/synchronization.md)
and [collaboration guide](https://github.com/jamie950315/claudex/blob/v1.0.2/docs/collaboration.md)
for the exact boundaries.
