# Claudex 1.0.1

> Historical release notes for 1.0.1. Capabilities, defaults and validation
> statements below describe that release. For current installation and behavior,
> use the [app guide](../app.md), [collaboration guide](../collaboration.md), and
> [synchronization guide](../synchronization.md).

This update improves long-running collaboration, recovery and messages to existing
Codex and Claude Desktop conversations.

## Changes since 1.0.0

- Remove the fixed work execution timeout. Native work continues until completion,
  failure or explicit cancellation; bounded API waits do not cancel work.
- Allow concurrent tasks in the same or overlapping workspace, including writable
  parents and children. Callers must coordinate shared files; there is no workspace
  lock or automatic conflict merge. Permission and directory-scope checks remain.
- Add guarded controller recovery for writable uncertain work after the operator
  inspects and reconciles its files. Resolution records the attestation and closes
  the old task as failed without replay, deletion or a false success claim.
- Send coordination notes by a unique exact native chat title. Ambiguous titles
  require selection. Known ended chats may queue messages for later resumption.
- Wake supported original Codex and Claude Desktop chats using their native
  owners, without creating replacement chats or external transcript writers.
  Durable claims prevent automatic replay after an unknown dispatch outcome.
- Load the Claude wake bridge from its separately verified active frontend asset,
  independently of sidebar or folder subscriptions, with bounded wait diagnostics.

## Using native-chat messages

Claude Desktop must remain open with the bridge loaded; the recipient chat does
**not** need to be selected. Busy work, drafts and permission prompts may delay
dispatch. Sending normally requests a wake and can consume native account
allowance; `wake: false` queues for hooks only. Queued notes are subject to expiry.

Native acceptance and a recipient ACK are separate: an ACK confirms receipt,
**not completion of the requested action**. The Claude frontend bridge is
version-pinned and may need adaptation after vendor updates. Loading a changed
bridge requires a normal idle Claude restart. Current native acceptance covers
same-chat wake and ACK on both providers, not every future frontend version.

## Distribution and limits

The graphical build targets Apple Silicon Macs running macOS 13 or later and
requires existing Codex/ChatGPT and Claude Desktop installations with native
account access. Required sign-ins, permissions and hook trust remain in effect.
Existing clients may need to refresh MCP connections.

This build is **Apple Development signed, not Developer ID signed or notarized**.
Clean-user/clean-machine installation acceptance has not been completed. Do not
disable macOS security controls to hide this limitation.

The 64-worker limit is a ceiling, not a native load certification or spending
guarantee. Uncertain work still blocks new dispatch until explicitly reconciled;
it is never silently replayed. See the [app guide](../app.md) and
[collaboration guide](../collaboration.md) for setup and precise boundaries.
