# Claudex 1.3.1

Development build of 2026-10-10; not yet a published release. App **1.3.1**
bundles Claude Mod **0.8.15**. The bundled Mod payload is unchanged. These notes
summarize changes since 1.3.0.

## Desktop adapters cannot break the code they attach to

- Every statement Claudex injects into a Claude frontend module now contains its
  own failures. Wake signals and folder-store calls catch, and each runtime
  bootstrap falls back to an inert object. A wrong match or a runtime that
  fails to start loses a Claudex signal; it no longer can stop a native send, a
  render or the vendor module's evaluation.
- Installed adapter resources are rewritten with this form. They take effect
  after a normal idle Claude restart.

## Recognition follows declarations and values instead of shapes

- Identifiers are resolved to their declarations by a lexical scope analysis.
  A parameter, block binding, hoisted `var`, catch or loop binding and a write
  from a nested function are recognized as such; a property or an unrelated
  parameter that merely shares a minified name is no longer counted.
- 1.3.0 and earlier accepted a send whose own hoisted `var` hid the getter it
  appeared to call, and patched it with a call that failed. Such sends are now
  refused, and the injected name is checked at the scope where it is placed.
- Owner-wake callbacks are found by following values. A binding is every
  function its declarators and assignments can give it, and exactly one must
  remain. Compiler memo slots count only when every write to the slot stores
  that callback. A memo helper counts when its own body returns one argument
  unchanged and writes only into the cache it is given, whatever its loops and
  branches look like.
- The session a send reads may be a getter call, a retained React ref or a
  getter that returns such a ref. A retained ref may be read any number of
  times; a bare use, an update, a delete or a write other than its selection
  mirror still refuses it.
- Which dependencies invalidate a memo cache is no longer compared: it cannot
  change which function is stored.

## Verification

- A differential mutation test inserts one or two binding forms into synthetic
  components (about 9,000 mutants). Every accepted mutant must behave exactly
  like its unpatched source and never signal a session the send did not use.
  Run against the 1.2.41 recognition it reports 18 mutants that break the send.
- All 30 saved real frontend builds pass static acceptance, and each receives a
  byte-identical owner-wake patch from the previous and the new resolver.

The native session-switch report was evaluated as a wake source and not
adopted: it is gated telemetry, absent from the August builds, and a Remote
Control send has no native counterpart.

This is not live acceptance. No Claude restart, owner wake or message
reception was exercised with this build.
