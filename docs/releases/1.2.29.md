# Claudex 1.2.29

Development build of 2026-10-09; not yet a published release. App **1.2.29**
bundles Claude Mod **0.8.15**. The bundled Mod payload is unchanged from App
1.2.27. App and Mod versions are separate. These notes summarize changes since
1.2.28.

## Background commands that finish late no longer pause a conversation

A Codex command started in one turn can finish after that turn has closed.
Codex then lists the result inside the old turn, which changes history Claudex
has already synchronized. Claudex keeps that history unchanged by rendering the
result at the point it actually arrived, after proving that point from the
original rollout. That proof covered one case only: Codex was idle, the
boundary was a completed turn with a reply, and every recorded field had the
exact expected shape. Anything else paused the conversation with `late arrival
has an ambiguous identity, active turn or completion order`.

A survey of the reviewed machine's rollouts found 172 late completions in 56
conversations. The proof now covers the forms observed there:

- The command finishes while a later turn is running. Its boundary is the
  newest turn already closed at that moment.
- The boundary or the command's own turn was interrupted, failed, or was a
  compaction-only turn without a reply.
- The boundary is a trailing compaction-only turn that is not exported yet. The
  command is held back with it and appears right after it once a later reply
  completes.
- The completion was recorded a few milliseconds before its row was written,
  has no start time (earlier Codex versions), has an empty output that the API
  reports as null, or ran in a directory other than the conversation's.
- Codex added metadata fields to header or context rows. Only the fields that
  order the command are compared.
- The rollout file is readable by other users, which is how Codex writes most
  of them. The proof previously refused every such file before reading it;
  group or world write access is still refused.
- An earlier checkpoint already holds some late commands inside their own turn.
  Those stay there and only later arrivals use their boundary.

The complete saved checkpoint must still match, the command must equal the API
item exactly, and nothing in a native file is changed. Of the 29 tracked
conversations with late completions on the reviewed machine, 13 now pass a
forced proof instead of 1, including both that were paused.

Still paused when a late completion changes synchronized history: a rollout
continued from an earlier segment, overlapping turn lifecycles, a command whose
text Codex redacted in the API, the oldest rollout format, and late items that
are not commands. On the reviewed machine 14 conversations are in these groups;
they synchronize normally until such a completion arrives.
