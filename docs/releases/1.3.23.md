# Claudex 1.3.23

Development build of 2026-10-11; not yet a published release. App **1.3.23**
bundles Claude Mod **0.8.22** (unchanged). These notes summarize changes since
1.3.22.

## Readers of native data refuse real problems, not unfamiliar forms

Codex and Claude change their saved formats with every release. Until now a
reader accepted the forms it had seen and paused a conversation on anything
else, so each release could need a new Claudex build. The rule is reversed: a
reader names what is a real problem and accepts the rest.

- **Empty Codex turns.** A turn Codex reports as completed with no items is
  left out when its rollout shows no activity: no reply, reasoning, tool call
  or output, token or usage record, item completion, compaction or authored
  input, and no record elsewhere that names the turn. Unknown records,
  events, state, context kinds and extra fields no longer matter, and the
  separate list of app-message forms after such a turn is gone.
- **Late command results.** Fields a release adds to the lifecycle, command
  or frame records are ignored, a time the rollout did not record is not a
  contradiction, and output copies an older runtime did not write are not
  required. The projected command must still equal the item Codex reports.
- **User input of an unknown kind** is kept whole as inert labeled data
  instead of pausing the conversation. Input that points at content the
  history does not contain (a path, URL or file ID) is still refused.

Still refused, because these are real problems: content that cannot be
carried over, a contradiction with what the native app reports or with a
saved checkpoint, an identity or owner that does not match, an unstable or
unsafe file, and any uncertain write. Writing, archival, ownership and the
frontend patches keep their exact checks.

Checked over the local rollouts in both directions: all 35 real empty turns
are accepted, and of 2,341 real turns with activity presented as empty none
is accepted.
