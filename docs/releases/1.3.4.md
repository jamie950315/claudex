# Claudex 1.3.4

Development build of 2026-10-10; not yet a published release. App **1.3.4**
bundles Claude Mod **0.8.15**. The bundled Mod payload is unchanged. These notes
summarize changes since 1.3.3.

## Claudex asks for a Claude restart when it cannot make one itself

- After a frontend update Claude Desktop runs files that were loaded before
  Claudex prepared them. When the one-time automatic restart does not apply
  (Claude has been open for more than a minute, a Code session is running, a
  prompt was submitted, the restart was declined or already used, or the
  automatic restart is disabled), the app now shows **Restart Claude to finish
  updating** and sends a notification with the same request. Previously only a
  status file recorded it.
- The request ends by itself once Claude Desktop has been started after the
  files were written, and it is never shown while Claude is not running.
  Blocked conversations and other synchronization problems keep priority.
- While a late frontend file is still expected, the request is held back until
  Claude is no longer newly started, so it does not appear moments before an
  automatic restart.
- A Claude Desktop that was restarted by hand after the last write is no longer
  restarted again automatically.
- The title and text are localized in all nine app languages.

Checked with injected process, clock and status data. The notification and the
automatic restart have not yet been observed on a real frontend update.
