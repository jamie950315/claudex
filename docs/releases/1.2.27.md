# Claudex 1.2.27

Released on 2026-10-06. App **1.2.27** bundles Claude Mod **0.8.15**.
[Release and downloads](https://github.com/jamie950315/claudex/releases/tag/v1.2.27).
The bundled Mod payload is unchanged from App 1.2.26. App and Mod versions are
separate. These notes summarize changes since the last published release, 1.2.26.

This release removes holds that stopped synchronization or work without
protecting anything, and lets several leftover states recover on their own.
History, checkpoint, ownership and no-replay checks are unchanged.

## A failed delivery no longer stops every conversation

- Claudex keeps one delivery transaction at a time. When its recovery failed,
  the watcher exited and its supervisor restarted it into the same failure, so
  nothing synchronized. Desktop mode had no way to give that transaction up.
- A prepared delivery of a new Codex copy that provably wrote nothing natively
  (its planned rollout file is absent and Codex does not know the thread) is
  now dropped when its recovery fails. Only its conversation is held, with the
  failure as the reason, and the next synchronization plans a fresh delivery.
  `claudex abort` does the same explicitly in Desktop mode.
- Every other failed recovery stays visibly blocked on its transaction and is
  retried by the next pass instead of ending the watcher. Applied, promoted,
  owner-reusing and original-archive transactions are never dropped.

## Leftover locks no longer keep the service from starting

- A lock was considered held whenever any process had its recorded PID. After
  an unclean shutdown another process often reuses that PID, and the service
  then refused to start; `recover-lock` refused too. A process born more than
  two seconds after the lock was written is now recognized as a reused PID.
  This applies to coordinator, supervisor and Claude owner locks. A start time
  that cannot be read still counts as a live holder.
- A lock still empty after a minute and a recovery claim left for a minute are
  reclaimed. A Claude owner lock without a recorded child process blocks a
  start only while a parentless process under a Claude path born with that lock
  exists.

## Conversations that waited or were held without a way back

- A conversation that only waited during the startup check (for example
  because its file changed while being read) gets the same three bounded
  follow-ups as a completion event. Before, it was not looked at again until
  its next event, so a completion made while Claudex was stopped could stay
  undelivered.
- A Claude rewind leaves the replaced turns in the transcript as a sibling
  branch, which was refused as nonlinear history. The decoded history now
  follows the branch ending at the last authored row when each fork on it
  continues with a real user prompt. A second assistant reply or competing tool
  results are still refused, and a rewind that removes turns already
  synchronized still stops at the saved-prefix check.
- When Codex moves a conversation to another project while the old directory
  still exists (for example into a worktree), that conversation's own
  synchronization now asks Codex for the move and follows it. Unmoved
  conversations still never contact the backend for this.
- A Claude owner block written to disk was never cleared. A block recorded by
  one Claudex version is now judged again by another through the normal
  checkpoint checks.

## Size limits

- The history client's frame limit follows a raised `nativeHistoryMaxBytes`
  (at least 64 MiB), and a response above it is reported as such instead of as
  an unavailable request. A delivery packet is still limited to 64 MiB.
- The launcher between Codex Desktop and its backend carried the same 64 MiB
  frame limit for Codex Desktop's own traffic and stopped the backend when a
  frame exceeded it. It now uses a 1 GiB sanity bound. This takes effect the
  next time Codex Desktop starts.
- Rollout files read for empty-turn, initial-goal and late-command proofs may
  be up to 480 MiB instead of 64 MiB.
- Dependency anchors and frozen copies that exceed the backup quota are
  reported and no longer pause every delivery, because none of them can be
  removed. A removable copy that cannot be retired still pauses.

## Collaboration and Mod

- One unreadable process table no longer ends every tracked worker. Tracking
  ends only when the table stays unreadable for ten seconds; each worker's own
  identity checks still fail immediately.
- The Mod installation check accepts any native-generated
  `types/<package>/index.d.ts` and the orphan marker in its cache, instead of
  three known packages. Additional scripts, skills and packaged files are still
  reported as a mismatch.

## Verification

The complete source gate passed **1,992 tests**, with zero failures and 23
explicit opt-in native skips. The same suite passes with the runtime
temporarily defaulting to a 256 MiB budget and five-turn pages, apart from the
one test that pins the defaults. With the opt-in native tests enabled against
Codex 0.160.0 in isolated temporary homes, the Desktop adapter, projection and
owned-history tests pass, including alternating deliveries through a real
Codex app-server; seven legacy CLI-mode tests stop at their version gate for
this unvalidated Codex version, as before. No model inference is started.

The release ZIP was extracted; all **139 packaged engine/Mod files** and **nine
locale catalogs** matched the source, and strict deep signature verification
passed. On the Mac used for verification, the installed 1.2.27 app with a 256
MiB budget completed verification of **407/407 conversations** with zero
restarts and zero synchronization blocks, and reports the unchanged Mod as
current. None of the failure states above was present on that Mac after
installation, so each change rests on its automated tests and the isolated
native run rather than a live occurrence. The rewind handling has not been
checked against a transcript produced by a real rewind. This is an
installed-Mac check, not a clean-machine or blanket certification of every
native version.

## Updating

Replace the app through a normal idle shutdown and reopen it. Restart Codex
Desktop when convenient so its launcher uses the new frame bound. Existing
Claude Code sessions keep their loaded Mod; this release does not change it.
Installation does not force-close native work, replay uncertain input or trust
Codex hooks automatically.

## Distribution

The download targets **Apple Silicon Macs running macOS 13 or later** and bundles
portable Node/npm and production dependencies. Existing compatible Codex/ChatGPT
and Claude desktop apps, native sign-ins, permissions and native hook trust remain
required. Vendor desktop apps, credentials, private state and transcripts are not
bundled.

This build is **Apple Development signed, not Developer ID signed or notarized**.
It does not establish frictionless Gatekeeper acceptance on every other Mac.
Do not disable OS verification to conceal that limitation.
