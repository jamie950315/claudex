# Claudex 1.4.0

Released on 2026-10-11. App **1.4.0** bundles Claude Mod **0.8.22**.
[Release and downloads](https://github.com/jamie950315/claudex/releases/tag/v1.4.0).
App and Mod versions are separate. These notes summarize changes since the
last published release, 1.3.0 (Mod 0.8.15); the development builds 1.3.1 to
1.3.26 have their own notes.

This release stops conversations from pausing only because Codex or Claude
changed a saved format, lets Claudex finish a Claude frontend update by
itself, and makes cache warming configurable. Writing, archival, ownership,
checkpoint and no-replay checks are unchanged.

## Conversations no longer pause on unfamiliar native formats

Codex and Claude change their saved formats with every release. A reader used
to accept the forms it had seen and pause a conversation on anything else.
The rule is reversed: a reader names what is a real problem and accepts the
rest.

- **Empty Codex turns.** A prompt a hook blocks, such as `/claudex:warm on`,
  leaves a turn with no reply. It is left out when its rollout shows no
  activity, wherever it was submitted from (composer, queue, iOS remote, a
  goal, an agent). Unknown records, state fields, context kinds and extra
  fields no longer matter.
- **Late command results.** Fields a release adds are ignored, and a time the
  rollout did not record is not a contradiction.
- **User input of an unknown kind** is kept whole as inert labeled data.
- **Claude branches.** Every fork in a transcript is read the way the Claude
  app resumes it: the conversation is the branch ending at the last message.
  Only three exact shapes were read before.
- **Claude `/compact`.** How Claude flags the summary or describes the segment
  it kept is no longer compared. A repeated copy of earlier rows and a
  boundary naming a row Claude never saved (both observed on Claude Code
  2.1.295) no longer pause the conversation.
- **Codex provider switch.** An account tool that rewrites the provider label
  in every rollout header no longer pauses a conversation whose earlier
  snapshot is kept for dependent threads.
- **Images before a Codex rollover** are accepted when the new rollout's own
  reference to the previous file covers their turn.

Still refused, because these are real problems: content that cannot be carried
over, a contradiction with what the native app reports or with a saved
checkpoint, an identity or owner that does not match, activity in a turn
claimed empty, a missing parent or unpaired tool call, earlier history missing
before a compaction, an unstable or unsafe file, and any uncertain write.

Checked over the local histories of the development Mac: 1,560 Codex rollouts
(all 35 real empty turns accepted; of 2,341 turns with activity presented as
empty, none accepted) and 537 Claude transcripts (all decode; every transcript
that decoded before gives identical messages). The agent-initiated empty turn,
new fork shapes, the relaxed late-result fields and a real provider switch are
covered by synthetic tests only.

## Claude frontend updates finish without a second manual restart

- When Claude Desktop fetches a new frontend it evaluates those files before
  Claudex can prepare them. Claudex now restarts Claude itself, only while
  Claude has just been opened: at most one minute old, no prompt submitted
  since it started, every enabled adapter installed. It asks the application
  to quit and reopens it, never signals the process, and restarts at most
  twice in ten minutes. A draft typed in that first minute is not observable
  and can be lost.
- Otherwise the app shows **Restart Claude to finish updating** and sends the
  same notification, in all nine languages. The request survives a Claudex
  restart and ends once Claude has been started after the files were written.
- `rendererAdapters.relaunchAfterUpdate: false` disables the automatic restart.
- Everything Claudex injects into a frontend module contains its own failures:
  a wrong match can lose a Claudex signal but can no longer stop a native
  send, a render or the module's evaluation.
- Recognition resolves identifiers to their declarations and follows values
  instead of comparing shapes. A send whose own hoisted variable hid the
  getter it appeared to call was patched with a failing call in 1.3.0 and is
  now refused.
- The brief error shown while Claude rewrites its cache at startup is reported
  as a check for up to sixty seconds.

The automatic restart was observed once on a real frontend update
(2026-10-10) and in one live rehearsal. All 30 saved real frontend builds pass
static acceptance. Future frontends are matched on a best-effort basis.

## Cache warming

- `/claudex:warm on` takes one limit, on Claude and on Codex: `rounds=N` (up
  to 500), `for=90m|3h|1h30m` (up to 168 hours) or `until=HH:MM` or
  `until=DD:HH:MM`. Without one it warms for four hours (it was 60 minutes and
  3 requests, which at a 1h TTL fitted one request). At a 5m TTL that default
  allows up to 60 requests; give a limit when that is not wanted. More
  requests use more plan quota.
- The default limit is one setting shared by Claude, Codex and the app. Change
  it in the Mod's Cache tab, with `/claudex warm limit for=6h`, or in the app.
- **Cache settings…** in Claudex.app (footer and menu) opens a window with the
  default limit, the startup cache TTL (Claude Code only), what your own
  message does to a running warm-up, and the conversations being kept warm,
  each with Stop. Only Save and Stop write anything.
- **When you send a message**: *Keep warming and start the limit over* (the
  default: `for=4h` runs four more hours from the reply, `rounds=3` allows
  three more; an `until=` end keeps its clock time) or *Stop warming*.
- Codex warming works on runtimes after 0.160.0, including 0.162, which sends
  settings only when they change.
- The warming ledgers no longer fill up for good: finished bookkeeping of
  stopped, expired warm-ups is retired when half the space is used.

Claude Mod 0.8.22 carries the command, summary and setting changes. A Claude
session that already loaded an older Mod keeps it until a new session. These
changes were checked with injected data, the native validator and the native
test kit; no real warming inference was run for this release.
