# Claudex 1.2.28

Development build of 2026-10-09; not yet a published release. App **1.2.28**
bundles Claude Mod **0.8.15**. The bundled Mod payload is unchanged from App
1.2.27. App and Mod versions are separate. These notes summarize changes since
1.2.27.

## Completion hooks shared with another tool stay configured

- Claudex recognized its completion hooks only when the whole hook group in
  the native settings was exactly the one it installed. When another tool or a
  manual edit added a handler to that group, the app reported that the hooks
  were not configured and paused synchronization, although the hooks still ran.
  Setup could not repair it either: it refused the group as an unrecognized
  Claudex hook.
- The exact Claudex handler is now recognized inside a group that is otherwise
  identical (same matcher, no other fields). Such a group counts as configured
  and setup leaves it as written. An update removes only its own superseded
  handler from the shared group and adds the new one as a separate group; the
  other tool's handlers stay in place.
- An altered Claudex handler, or one in a group with a different matcher, is
  still refused and reported, as before.

## A Desktop session that never started no longer blocks predecessor archival

- Claude Desktop writes a session's registry record before its CLI session
  exists, for example for a Remote Control session that never ran. One such
  record made every registry lookup fail with `Ambiguous Desktop session
  registry identity`, which held native predecessor archival for all
  conversations.
- A record whose filename matches its session ID and that has no CLI session ID
  at all is now skipped: it maps to no native transcript. Its Desktop identity
  stays protected. A record with an invalid CLI session ID or a mismatched
  session ID still fails the lookup.
