# Claudex 1.1.1

Released on 2026-10-03. App **1.1.1** bundles Claude Mod **0.7.1**.
[Release and downloads](https://github.com/jamie950315/claudex/releases/tag/v1.1.1).
This is the release record; use the maintained [app](../app.md),
[Mod](../claude-mod.md) and [collaboration](../collaboration.md) guides for current
instructions. Release tags and their original source snapshots are not rewritten
when documentation is clarified later.

## App-managed Mod lifecycle

- Setup and normal app startup install or update the bundled Mod through the
  native plugin manager. End users do not need separate Mod staging, Git, Node
  installation or a compiler.
- A private recovery journal preserves verified previous sources, old versions,
  both native configuration identities and explicit disabled/receiver preferences.
  Newer installed versions are not downgraded.
- Missing management capabilities use a separately pinned, integrity-checked
  official manager, not replacement of an existing inference CLI.
- Installed version and fresh loaded-session observations are shown separately.
  Status inspection does not install software or start model work.

## Proactive collaboration and visibility

- Supervisors can send questions or direction changes while a child is running,
  without waiting for a child blocker or its entire invocation to finish.
- Generation-fenced check-in and eligible worker MCP response boundaries provide
  same-invocation instruction context. Exact accepted/rejected acknowledgements
  consume instructions for continuation scheduling without claiming completion.
- Opted-in managed-child milestones can resume a waiting parent before the child
  finishes. Duplicate reports and consumed notices do not schedule duplicate work.
- The 15-tool MCP interface includes public work events, complete worker reports,
  cooperative controls and scope-checked reads of declared artifacts.
- Wait defaults are five minutes, with an explicit maximum of thirty minutes.
  Wait timeouts do not cancel work; native-host deadlines remain independent.
- Completed-result review annotations no longer create duplicate completion wakes.

## Verification and boundaries

The release ZIP was extracted and compared with its source: all 127 packaged
engine/plugin files and nine app locale catalogs matched, and strict deep code
signature verification passed. The Mod manifest was 0.7.1 with empty user-specific
path defaults and both receiver opt-ins off. The official Mod validator passed
without errors/warnings and the native test kit passed 18/18 in its separately
authorized test process.

Real Codex-to-Claude and Claude-to-Codex supervisor/child acceptance completed all
four native invocations in generation one. Each child accepted its supervisor's
new target without a prior blocker, the fixture stayed unchanged, and recorded
owned process groups exited. This is cooperative tool/check-in-boundary delivery,
not immediate interruption of a long-running native tool or new Desktop idle-wake
acceptance. See the [verification scope](../collaboration.md#verification-scope).

Existing Claude sessions can retain an older loaded Mod; open a new Code session
and submit `/claudex`. Existing MCP connections can retain older tools until
their normal reconnect/host lifecycle refresh. Installation does not force-close
native work or replay uncertain input.

## Distribution

The download supports Apple Silicon Macs running macOS 13 or later. Existing
Codex/ChatGPT and Claude desktop apps, native account access, permissions and hook
trust remain prerequisites. Vendor apps and credentials are not bundled.

This build is **Apple Development signed, not Developer ID signed or notarized**.
Isolated fresh-profile and installed-Mac checks do not establish clean-machine
Gatekeeper acceptance on every other Mac. Do not disable OS verification to hide
that limitation.
