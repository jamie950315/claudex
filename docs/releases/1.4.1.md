# Claudex 1.4.1

Development build of 2026-10-12; not yet a published release. App **1.4.1**
bundles Claude Mod **0.8.23**. These notes summarize changes since 1.4.0.

## A finished warm-up compacts its Claude Code conversation

- When a Claude Code warm-up reaches its limit, Claudex now compacts that
  conversation once, shortly before the cache of its last warm request
  expires: 5 minutes before at a 1h TTL, 1 minute before at 5m. The summary is
  made while the conversation is still cached, and your next message starts
  from a small context instead of a full-price read. This is **on by default**.
- It is the native compaction `/compact` runs, made by the Mod directly. It is
  not a prompt, and its one model request is not counted as a warm request.
- In the Cache settings window, **When warming ends** (Claude Code only)
  chooses between compacting and leaving the conversation as it is. The Mod
  pane's Cache settings tab and `/claudex warm compact on|off` save the same
  shared setting. It applies to warm-ups already running.
- `/claudex:warm on compact=off` (or `compact=on`) decides for that session
  only.
- Nothing is compacted when the cache has already expired, a draft is in the
  composer, the conversation is busy, or you sent a message of your own after
  the limit ran out. A warm-up you stopped, or one that failed, compacts
  nothing. A compaction is attempted once and never repeated.
- `/claudex:warm status` shows whether and when the conversation will be
  compacted.
- This needs a conversation that loaded Mod 0.8.23; an older loaded Mod keeps
  warming as before and compacts nothing. Codex warm-ups are never compacted.

Checked with injected data, the native validator and the native test kit. No
real compaction was run for this build.
