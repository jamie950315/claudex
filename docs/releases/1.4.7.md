# Claudex 1.4.7

Released on 2026-10-14. App **1.4.7** bundles Claude Mod **0.8.24**, unchanged.
[Release and downloads](https://github.com/jamie950315/claudex/releases/tag/v1.4.7).
App and Mod versions are separate. These notes summarize changes since the
last published release, 1.4.6.

## Codex conversations older than a week are read again

- Codex 0.162 compresses a rollout left unchanged for seven days to
  `<name>.jsonl.zst` and restores the plain file before its next append,
  while its API keeps reporting the plain path. Every tracked conversation
  older than a week paused as "unavailable at its saved path".
- Claudex now reads whichever form is present, proves the identity of that
  file and reads its decompressed content. A conversation is unavailable
  only when neither form exists.

## A project folder reached through an alias no longer pauses conversations

Renaming a project folder (for example `~/Documents/Codex`) and leaving a
symlink at the old name exposed several gaps:

- Codex records the directory a thread was started in, which can be the
  alias, while its API may report either spelling. The checks Claudex runs
  on Codex rollouts now accept a recorded directory when it resolves to the
  same folder, instead of requiring the same string.
- Claudex-owned Codex snapshots, dependency anchors and preserved originals
  keep their saved directory string while Codex reports the same folder.
  Only a current, unmanaged original follows a Codex project move.
- A relocation no longer waits forever behind a tail of failed turns; only a
  turn still in progress makes it wait.
- A held Claude owner restores bound original images, as a running owner
  does, instead of authenticating against resized previews.
- Compressed rollouts report their logical size, so dependency anchor checks
  no longer fail on a size mismatch.

## Fewer pauses from late Codex items

- A Codex backend restart ends a running turn without a closing record. The
  check for late commands and sub-agent notifications refused the whole
  rollout for that. The open turn now stays open and is never used as a
  boundary; a later record closing it still pauses.
- A usage tool such as `ccusage-codex` may hard-link Codex rollouts into its
  own cache. The rollout checks refused a file with a second link as unsafe,
  pausing the conversation with "source must be an owned, single-link bounded
  regular file". They only read the file and already prove its exact identity
  before and after reading, so an extra link is accepted. Group or world write
  access is still refused.

## Claude owners and Remote Control

- Opening a conversation while Claudex was delivering another one left it
  disconnected until that delivery finished, up to 48 seconds in the observed
  case and for the whole startup check after a restart. Claudex now starts a
  requested Claude owner between the steps of a running pass, under the same
  lock and guards.
- A first Remote Control registration answered with an explicit CLI failure
  kept the conversation blocked across restarts. Claudex now resets that
  registration and replaces the process at its next idle use. Any other
  failure still leaves the outcome unknown and is not retried.
- A Claude Desktop registry lookup that overlapped a write to another session
  failed and held an idle conversation as changed. The lookup now repeats the
  whole scan up to three times and uses only a scan that saw no change.
- A long history check could miss the 300 ms delivery deadline of the
  watcher's own events and end the watcher. The watcher now wakes itself
  directly; the deadline still applies to other processes.

Each problem was found in real use on one Mac and is covered by synthetic
tests. The hard-link fix was installed locally and the paused conversation
was synchronized again on its next startup check.

## Distribution

Apple Silicon, macOS 13 or later. The app has a development signature and is
not notarized.
