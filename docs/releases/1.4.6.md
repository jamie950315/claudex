# Claudex 1.4.6

Released on 2026-10-13. App **1.4.6** bundles Claude Mod **0.8.24**, unchanged.
[Release and downloads](https://github.com/jamie950315/claudex/releases/tag/v1.4.6).
App and Mod versions are separate. These notes summarize changes since the
last published release, 1.4.5.

## A Claude conversation continued from Codex uses your permission mode

- Claudex starts the Claude process of such a conversation through the Claude
  Agent SDK, which always starts it in the `default` permission mode and
  ignores `permissions.defaultMode` from Claude Code settings. That process
  has no approval window of its own, so in a turn sent from Claude Desktop
  every tool that would have asked was denied: shell commands "require
  approval" and connector tools were "not granted yet", even with
  `bypassPermissions` configured.
- Claudex now reads the mode you configured and starts the process in it, as
  a session you start yourself would. The highest settings tier that names a
  mode decides, but a project's committed settings cannot raise it to
  `bypassPermissions`, `auto` or `acceptEdits`. Bypass is not requested when
  policy disables it or when running as root. With no configured mode,
  nothing changes; Claudex never picks a mode for you.
- The mode is read when the process starts. An already running conversation
  picks it up after Claudex restarts, which updating the app does.

Found in one real conversation. Reproduced without model use against Claude
Code 2.1.283: the user and flag settings tiers both started in `default`,
and only an explicit mode took effect. After the fix a restarted conversation
process was observed starting in `bypassPermissions`. Also covered by
synthetic tests.
