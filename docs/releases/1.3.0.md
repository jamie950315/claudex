# Claudex 1.3.0

Released on 2026-10-10. App **1.3.0** bundles Claude Mod **0.8.15**.
[Release and downloads](https://github.com/jamie950315/claudex/releases/tag/v1.3.0).
The bundled Mod payload is unchanged from App 1.2.27. App and Mod versions are
separate. These notes summarize changes since the last published release,
1.2.27; the development builds 1.2.28 to 1.2.41 have their own notes.

This release keeps the Claude Desktop integrations working across frontend
updates, and removes several holds that paused synchronization without
protecting anything. History, checkpoint, ownership and no-replay checks are
unchanged.

## Desktop integrations follow Claude frontend updates

- Folder placement, chat wake, owner wake and the `/claudex` command entry are
  located by import, syntax and native-binding relationships instead of one
  build's chunk and compiler shape. Compiler memo helpers, callback aliases,
  re-exports, retained React refs, `React.memo` wrappers and older native
  binding forms observed between July and October 2026 are recognized.
- Searches stay bounded: eight modules for an import chain and twelve steps for
  a callback. Ambiguity, cycles, missing chunks, lexical shadows and unknown
  helper semantics still refuse installation, and the vendor resource, its
  immutable original and its journal stay as they are.
- Per-file cache and source limits are 4 MiB (from 2 MiB); observed chunks
  reach about 2.37 MiB. A length header whose digit count changes is rewritten
  only in the observed Chromium HttpResponseInfo v3 layout.
- Chat wake installed alone no longer blocks the shared folder resource, and
  opening a conversation while another one synchronizes still reconnects its
  Claude owner.
- New in 1.3.0: the retained-ref proof requires its three visible uses to be
  exactly the declaration, the effect mirror and the send read. A send-local
  variable of the same name combined with an escaped ref was accepted before
  and would have produced a failing send; it is now refused.

Static acceptance ran production discovery and installation on 30 real
frontend builds in isolated caches; all four adapters install on each. A July
build with missing archived dependencies could not be verified. This is not
live acceptance of every build: a newly installed resource takes effect after
a normal idle Claude restart, and future frontends are matched on a best-effort
basis.

## Normal waits are no longer shown as integration failures

- One immediate rediscovery after the frontend cache changes during inspection
  is shown as a check, and the hold while Claudex reopens is shown as a wait.
  Neither asks for action. A second failure, missing recovery evidence, access
  denial, lost notifications and map or history errors still do.
- Diagnostics keep one bounded last failure with fixed phase, code and times.

## Synchronization holds removed

- Completion hooks stay configured when another tool adds a handler to the
  same hook group.
- A Desktop registry record without a CLI session no longer blocks predecessor
  archival for every conversation.
- Codex background commands that finish after their turn closed are rendered
  at their proven arrival point in the forms observed on the reviewed machine,
  instead of pausing the conversation.
- A Claude conversation ending with a native local command such as `/compact`
  or `/model` is complete, and `/compact` run from Claude Desktop in a
  synchronized conversation no longer blocks it.
- New conversations whose working directory does not exist on this Mac are
  listed as absent sources and no longer ask for attention.

## Distribution

Apple Silicon, macOS 13 or later. The app has a development signature and is
not notarized.
