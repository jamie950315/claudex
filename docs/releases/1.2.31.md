# Claudex 1.2.31

Development build of 2026-10-09; not yet a published release. App **1.2.31**
bundles Claude Mod **0.8.15**. The bundled Mod payload is unchanged from App
1.2.27. App and Mod versions are separate. These notes summarize changes since
1.2.30.

## Chat wake finds its module in the current Claude frontend again

- The chat-wake adapter located Claude Desktop's session-action module by three
  markers that used to share one module. The frontend fetched on 2026-10-08
  moved two of them into other chunks, so no module carried all three and the
  adapter was skipped as `chatWake target module missing or ambiguous`. Idle
  Claude chats without a loaded Mod, and installations using the `renderer`
  wake route, could not be woken.
- When no module carries all three markers, the target is now the single
  module that passes the existing structural proof: the unique native
  LocalSessions import and its optional `forkSession` capability read. Builds
  that still carry the markers keep the marker selection. Two modules passing
  the proof without markers remain ambiguous and skipped.
- In the 2026-10-08 build that module is also the folder adapter's resource, so
  both are installed together as one shared resource with one journal.

Static acceptance (`dev/verify-claude-frontend-builds.mjs`) covers the 18
frontend builds cached on the reviewed machine: all four adapters install on
every build, and the only change from 1.2.30 is chat wake on the newest build.
Automatic re-application from the previous build to the newest one, repeated
installation and restoration pass in an isolated copy. The script's overall
result stays negative only for two obsolete owner-wake pins it reports by
design.

This is not live acceptance. A new adapter resource takes effect after a
normal idle Claude restart, and reception by an idle chat on this build still
has to be verified with a real message.
