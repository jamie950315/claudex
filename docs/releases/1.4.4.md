# Claudex 1.4.4

Released on 2026-10-12. App **1.4.4** bundles Claude Mod **0.8.24**, unchanged.
[Release and downloads](https://github.com/jamie950315/claudex/releases/tag/v1.4.4).
App and Mod versions are separate. These notes summarize changes since the
last published release, 1.4.3.

## Opening Claude's keyboard shortcuts no longer moves the chat wake

- Since the Claude frontend of 2026-10-08, the keyboard shortcuts dialog is a
  separately loaded file that carries the same markers Claudex used to find
  the place for its chat wake. The file is downloaded only when the dialog is
  first opened. After that, Claudex installed the chat wake into the dialog
  instead of the module Claude loads at startup, so after the next restart
  the wake did not start until the dialog was opened again, while the status
  still showed it as installed.
- The chat wake is now installed only in a module that Claude loads together
  with its entry file. A file that is loaded on demand is never chosen,
  whether or not it has been downloaded.

Nothing changes for an installation where the dialog was never opened. No
conversation, history or setting is affected.

Checked against the 21 Claude frontends saved between 2026-09-24 and
2026-10-10, both as cached on one Mac and as published in full: the same
module is chosen in every one, and no other integration changes. This is a
static check; reception in a running Claude Desktop was not re-verified for
this release.

## For contributors

`dev/check-claude-frontend-entry.mjs` checks one named Claude frontend without
Claude Desktop: it downloads the complete published module graph and runs the
production selection, transforms, syntax check and wiring contracts. Comparing
a complete graph with a cache is what exposed the defect above.

## Distribution

Apple Silicon, macOS 13 or later. The app has a development signature and is
not notarized.
