# Claudex 1.2.24

Released on 2026-10-06. App **1.2.24** bundles Claude Mod **0.8.15**.
[Release and downloads](https://github.com/jamie950315/claudex/releases/tag/v1.2.24).
The bundled Mod payload is unchanged from App 1.2.23. App and Mod versions are
separate. These notes summarize changes since the last published release, 1.2.23.

## One unreadable conversation no longer stops other deliveries

- Before a new delivery allocates a copy, Claudex verifies the other tracked
  conversations so that retention never retires something it cannot prove. In
  1.2.23, any one of them failing that verification stopped the delivery. A
  single unreadable conversation therefore stopped every Claude-to-Codex
  delivery and the first mirror of every new conversation. Only appends to an
  existing managed Claude owner continued.
- Such a conversation is now held on its own, like one whose working directory
  is missing: none of its copies is retired, they still count toward the backup
  quota, and it stays visible as blocked in the status. Its own synchronization
  keeps the same explicit hold.
- A failure in the delivering conversation itself, an unavailable Codex backend
  and an exceeded backup quota still stop the delivery. Explicit collection
  (`claudex gc`) still reports every failure.

## Claude tool result written before its call

- Claude Code can persist a tool result one row before the assistant row that
  issued the call (observed 11 ms apart, with a coherent parent chain). Claudex
  validated the parent chain but decoded rows in file order, reported
  `Unpaired tool result; handoff paused.` and held the conversation.
- Such a result is now decoded directly after its exact parent call. Every
  other row keeps its position, so existing checkpoints are unchanged. A result
  naming a call its parent never issued is still refused. Native transcripts are
  not rewritten.

Collaboration and cache warming are unchanged.

## Verification

The complete source gate passed **1,979 tests**, with zero failures and 23
explicit opt-in native skips. The release ZIP was extracted; all **139 packaged
engine/Mod files** and **nine locale catalogs** matched the source, and strict
deep signature verification passed. Publication does not start new model work
or interrupt native sessions.

On the Mac that showed the failure, the installed 1.2.24 app resumed the held
conversation from its saved checkpoint, created the missing Claude counterparts
of the four conversations enrolled while deliveries were stopped, and completed
verification of **407/407 conversations** with zero synchronization blocks. The
unchanged Mod 0.8.15 installation reports as current. This is an installed-Mac
check, not a clean-machine or blanket certification of every native version.

## Updating

Replace the app through a normal idle shutdown and reopen it. Existing Claude
Code sessions keep their loaded Mod; this release does not change it.
Installation does not force-close native work, replay uncertain input or trust
Codex hooks automatically.

## Distribution

The download targets **Apple Silicon Macs running macOS 13 or later** and bundles
portable Node/npm and production dependencies. Existing compatible Codex/ChatGPT
and Claude desktop apps, native sign-ins, permissions and native hook trust remain
required. Vendor desktop apps, credentials, private state and transcripts are not
bundled.

This build is **Apple Development signed, not Developer ID signed or notarized**.
It does not establish frictionless Gatekeeper acceptance on every other Mac.
Do not disable OS verification to conceal that limitation.
