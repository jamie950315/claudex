# Claudex 2.0.0

Released on 2026-10-17. App **2.0.0** bundles Claude Mod **0.8.49**.
[Release and downloads](https://github.com/jamie950315/claudex/releases/tag/v2.0.0).
App and Mod versions are separate. These notes summarize changes since 1.4.8
(Mod 0.8.31).

Claudex 2.0.0 replaces the JavaScript engine with a native Rust runtime while
preserving existing state roots, canonical checkpoint bytes, authenticated
archives, native account workflows, and the Swift macOS interface.

## Native Rust runtime

- The synchronization coordinator, history codecs, collaboration broker, MCP
  work tools, cache-warming scheduler, renderer maintenance, Mod manager, and
  CLI entry points now run as a single native Mach-O executable (`claudex`)
  built from the Cargo workspace (`claudex-core`, `claudex-sync`,
  `claudex-work`, `claudex-app`, and `claudex-cli`).
- `Claudex.app` embeds the native `claudex` binary at
  `Contents/Resources/engine/bin/claudex` along with the Swift UI and
  allowlisted Mod assets. It no longer bundles a Node.js distribution or engine
  npm dependencies, and end users need no Git, Node.js, Rust toolchain, or
  terminal setup.
- Existing 1.4.x installations upgrade in place. Durable state formats,
  nanosecond file identities, canonical JSON serialization bytes, ownership
  proofs, and uncertain-write protections remain compatible.
- Host-required JavaScript remains only where the host application requires it:
  the Claude Mod companion, injected Claude Desktop frontend adapters, and
  Codex Desktop's OpenAI-signed Node process-chain bootstrap (which runs the
  Rust transport as a sibling sidecar over inherited control pipes to preserve
  native process ancestry).

## Performance and memory improvements

### Rust runtime vs. JavaScript reference

In paired alternating measurements on an Apple M5 Pro Mac using identical
history inputs, equal portable message outputs, and matching canonical
fingerprints (`e7bdaf0`):

- **CLI startup and status:** `claudex --help` and status median latency dropped
  from **62–67 ms** to **5.4–6.5 ms** (30 paired runs per workload).
- **History decode, portable projection, and fingerprinting:** six workloads
  across small, medium, and large histories improved **1.88–3.68×** (12 paired
  runs each).
- **Large Claude history processing:** median time fell from **90.59 ms to
  24.61 ms** (~3.68× faster), while process peak RSS dropped from **508.85 MiB
  to 80.19 MiB** (an **84.2%** reduction).
- **Large Codex snapshot processing:** median time fell from **90.06 ms to
  27.43 ms** (~3.28× faster), while process peak RSS dropped from **481.42 MiB
  to 138.18 MiB** (a **71.3%** reduction).
- **Broker idle footprint and bundle size:** idle resident memory fell from
  **72.20 MiB to 11.63 MiB** (an **83.9%** reduction), and the packaged
  `Claudex-v2.0.0-macOS-arm64.zip` distribution archive dropped from
  **145.58 MiB to 11 MiB** (a **92.4%** reduction). Empty-broker `list` RPC
  median latency moved from `0.0884 ms` to `0.1539 ms` per request while
  carrying additional renderer publication diagnostics.

### Subsequent Rust optimization passes

Three additional optimization passes on the Rust runtime further reduced CPU
time, synchronization latency, and peak memory without relaxing any file
stability, ownership, or cryptographic checks:

1. **In-place normalization and streaming canonical checkpoints (`e721bc9`):**
   eliminated redundant full-conversation cloning during portable projection,
   streamed canonical checkpoint bytes directly into SHA-256 without
   intermediate JSON value/string allocations, and sorted JSON object entries in
   a single pass. Across six codec workloads, median latency dropped another
   **8.0–12.3%**, full large sync pipelines dropped **6.1–7.9%**, and large
   Codex codec peak RSS fell an additional **45.3%** (**138.14 MiB → 75.55 MiB**).
2. **Runtime-detected ARM64 hardware SHA acceleration (`080ec01`):** enabled
   the upstream `sha2` `asm` backend with runtime CPU feature detection while
   keeping portable builds and software fallback. Large canonical fingerprint
   stages dropped **67.2%** on Claude (**10.16 → 3.34 ms**) and **72.0%** on
   Codex (**17.80 → 4.98 ms**), reducing full large Codex codec median time by
   another **56.4%** (**26.22 → 11.42 ms**), large Claude codec by **24.4%**
   (**24.47 → 18.50 ms**), and full large synchronization pipelines by
   **23.6–25.9%** (changed turns) and **20.1–28.8%** (no-change checks).
3. **Bounded read-only archive workers and borrowed normalization (`adcfc4f`):**
   authenticated archive loads larger than one 64-message page use up to four
   scoped read-only workers while keeping serial writes, input-ordered error
   reporting, exact task-local `FileIdentity` capture for cold verification,
   and all no-follow/ownership/digest checks. Combined with borrowing
   already-portable messages during validation, large changed-turn sync medians
   dropped a further **22.3%** for Claude → Codex (**647.13 → 503.10 ms**) and
   **14.0%** for Codex → Claude (**323.08 → 277.92 ms**), while large no-change
   checks dropped **21.7–23.6%** (to **49.46 ms** and **60.01 ms**).

These figures are bounded process CPU, latency, and peak-RSS measurements on a
shared-use Apple Silicon Mac; they do not measure model generation time, whole
system RAM, or battery life.

## Synchronization, Local archival, and cache warming

- **Superseded Codex turns during active tails (Mod 0.8.48):** when a newer
  Codex turn is actively running at the tail of a rollout, an earlier
  superseded turn that native metadata still reports as `inProgress` is
  normalized from its verified completed reply prefix instead of blocking the
  conversation. Truly incomplete or single-turn active histories remain held.
- **Codex warm-command routing and limit completion (Mod 0.8.46–0.8.47):**
  Codex `/claudex:warm` hooks connect directly to the collaboration broker
  child root without duplicating the `collaboration` path component, and normal
  observer detachment preserves completed count, duration, and output limit
  reasons (`refresh-limit`) rather than overwriting them with
  `native-binding-changed`.
- **Claude Desktop Local handoff archival (Mod 0.8.43–0.8.45):** the native
  Code handoff consumer stays subscribed across sidebar grouping modes,
  inspects the unfiltered raw Code inventory, and verifies replacement
  conversations through the native exact-ID no-store metadata reader when a
  replacement is outside currently loaded sidebar pages. Starred conversations
  remain unarchived and protected original histories remain byte-for-byte
  intact.
- **History reader and watcher resilience (Mod 0.8.34–0.8.42):** excludes fresh
  Codex subagents using native API metadata, recognizes resumed no-query
  receipts with extended usage metadata, accepts intentionally quiet completed
  native turns (such as automation heartbeats), recovers proven interrupted
  image inputs, coalesces filesystem hint storms without overflowing watchers,
  and preserves durable-event wake handshakes and large watcher diagnostics.

## Verification

- **Automated suite:** 344 Rust workspace unit and integration tests passed
  (`cargo test --locked --workspace`, with 6 opt-in live-runtime tests ignored)
  plus 7 Node entry-point compatibility tests (`npm run test:entrypoints`),
  zero failures. The staged Mod `0.8.49` companion passed official strict
  validation (`claude plugin validate --strict`) and all 26 native Mod kit
  tests. The 1,042-case native Node.js JSON byte-equality oracle and 35 Rust
  frontend / 43 adapter checks across the 922-module native graph passed.
- **Installed Desktop synchronization and archival acceptance:** two existing
  long conversations (5,018 messages / 2 images and 2,640 messages / 17 images)
  completed full normal Runtime adapter reads on both Codex and Claude with
  matching canonical checkpoints and no incomplete tails. Three unstarred Local
  predecessors completed native archival (`isArchived=true`), one starred
  predecessor remained unarchived, and all 15 protected original histories
  (155,783,256 bytes) matched byte-for-byte afterward.
- **Live model synchronization, collaboration, and cache-warming acceptance:**
  verified a three-turn real-model synchronization roundtrip (`Claude -> Codex ->
  Claude`), a five-invocation cross-model collaboration delegation and handoff
  run (`Codex <-> Claude`), and live autonomous cache-warming primes, periodic
  refreshes, and limit stops on Claude (`claude-opus-5-5`) and Codex
  (`0.162.0-alpha.17.2` / `gpt-6.1-sol`). Detailed version-scoped records are
  in [the acceptance evidence](https://github.com/jamie950315/claudex/blob/v2.0.0/docs/agents/evidence.md).
