# Claudex 1.2.22

Released on 2026-10-05. App **1.2.22** bundles Claude Mod **0.8.15**.
[Release and downloads](https://github.com/jamie950315/claudex/releases/tag/v1.2.22).
The bundled Mod payload is unchanged from App 1.2.20. App and Mod versions are
separate. These notes summarize changes since the last published release, 1.1.1.

## Automatic synchronization recovery

- Conversations whose exact saved project directory is confirmed absent are
  automatically stopped from synchronization. Original history, checkpoints,
  records and attachments are preserved. Restoring the directory requires an
  explicit `resume-tracking` request; it does not silently re-enroll old work.
- Proven native command results arriving after their parent turn completed can
  retain their actual idle arrival boundary when the API inserts them into an
  old turn. The complete existing checkpoint and image identities must still
  match. Complete results are preserved; genuine edits, unknown native schemas
  and ambiguous lifecycle evidence remain blocked.
- Ordinary histories that already match their checkpoint retain the normal API
  export path. Large raw transcripts do not acquire the late-proof reader's
  additional size limit merely because they contain command events.
- Native empty/control turns and command envelopes have stricter, independent
  provenance checks. Control events do not become replies, close pending user
  requests or authorize history writes.
- Native origin and project-relocation evidence now uses exact nanosecond file
  identity checks. Original histories and native ownership guards remain intact.

## Opt-in native cache warming

- Claude Code provides a session-local `/claudex:warm on [5m|1h]`, `off` and
  `status` shortcut. One explicit `on` command enables its bounded policy after
  the native identity, idle-state, TTL and one-use checks.
- The Mod Cache settings pane exposes current native TTL and separately confirmed
  session-only, remember-last or fixed-default preferences for future sessions.
  Saved TTL preferences never enroll warming or start inference on their own.
- Normal shortcut/status responses use compact localized summaries. Read tokens
  remain accounted but have no Claudex admission ceiling; duration, refresh-count,
  output accounting and native lifecycle bounds remain.
- Codex Desktop 0.160.0 has a separate experimental best-effort adapter and
  `/claudex:warm` text command through its independently trusted native hook.
  The default refresh interval is 25 minutes. It uses the existing primary
  owner and keeps the model, effort and native settings unchanged.

Warming is **off by default**, consumes native account usage and creates real
visible conversation turns. Output budgets are not hard native per-request caps.
Codex composer draft visibility and per-turn no-tools enforcement are unavailable;
its prompts are advisory. Codex TTL is not configurable, and cache-retention
extension is not guaranteed. See the [cache-warming guide](../cache-warming.md)
for consent, limits and native hook requirements.

## Desktop and setup reliability

- The native `/claudex` panel is advertised in the eligible initial Claude Code
  command catalogue; the redundant above-prompt status band was removed.
- Claude sidebar adapters support additional native split-resource layouts and
  avoid shadowed React hook imports while preserving native grouping behavior.
- Setup handles observed fresh CLI-provider hardlinks and protected root-owned
  application bundles without relaxing private-state ownership or publisher checks.
- Native title-discovery failures and stale preparation notices are reported or
  cleared through their normal lifecycle instead of appearing successful.
- Current operational guides now match App 1.2.22 and Mod 0.8.15. Historical
  release records and their tagged artifacts retain their original snapshots.

## Verification

The complete source gate passed **1,975 tests**, with zero failures and 23
explicit opt-in native skips. The release ZIP was extracted; all **139 packaged
engine/Mod files** and **nine locale catalogs** matched the source, and strict
deep signature verification passed. Existing unchanged Mod validation and
authorized native acceptance are reused; publication does not start new model
work or interrupt native sessions.

The installed 1.2.22 app completed verification of **398/398 conversations** with
zero synchronization blocks. A real late-result conversation retained its complete
324-message prefix and image positions, then synchronized the complete 325th
historical event through five authenticated Claude packets. The original Codex
file remained unchanged. A separate **274 MB** native transcript retained its
complete 2,707-message checkpoint through the ordinary two-pass API path.
These are installed-Mac/native-history checks, not a clean-machine or blanket
certification of every native version or cache-retention scenario.

## Updating

Replace the app through a normal idle shutdown and reopen it. Existing Claude
Code sessions may retain an older loaded Mod; use a new ordinary session when
an update needs to load. Existing MCP connections refresh their catalogue through
normal reconnect/host lifecycle. Installation does not force-close native work,
replay uncertain input or trust Codex hooks automatically.

## Distribution

The download targets **Apple Silicon Macs running macOS 13 or later** and bundles
portable Node/npm and production dependencies. Existing compatible Codex/ChatGPT
and Claude desktop apps, native sign-ins, permissions and native hook trust remain
required. Vendor desktop apps, credentials, private state and transcripts are not
bundled.

This build is **Apple Development signed, not Developer ID signed or notarized**.
It does not establish frictionless Gatekeeper acceptance on every other Mac.
Do not disable OS verification to conceal that limitation.
