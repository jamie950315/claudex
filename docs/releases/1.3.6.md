# Claudex 1.3.6

Development build of 2026-10-10; not yet a published release. App **1.3.6**
bundles Claude Mod **0.8.15**. The bundled Mod payload is unchanged. These notes
summarize changes since 1.3.5.

## The restart request survives a Claudex restart

- The frontend entry, its written adapters and the time of the last write are
  now saved in `claude-relaunch.json`. Previously they lived only in the running
  watcher, so restarting or updating Claudex before restarting Claude removed
  **Restart Claude to finish updating** although Claude still ran the unprepared
  files.
- The saved request ends when Claude Desktop has been started after that write,
  when another frontend replaces it or when the automatic restart is made. A
  newly opened Claude Desktop still qualifies for the automatic restart after a
  Claudex restart.

## No brief error while Claude Desktop starts

- Claude Desktop rewrites its cache for some seconds while it starts. When both
  the frontend check and its one immediate repeat met a removed cache entry, the
  folder status showed an error for about ten seconds until the next cache event
  repaired it. Such a refusal is now shown as checking for up to sixty seconds
  from the first one, then reported as the same explicit failure as before.
- Nothing is inspected or retried when that minute ends; refusals with a
  permanent cause are reported at once, as before.

Checked with injected clocks, process data and cache failures. Neither change
has been observed on a real frontend update yet.
